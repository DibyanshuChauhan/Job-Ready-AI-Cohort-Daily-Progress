# 📦 node_modules

## What is node_modules?

The `node_modules` folder contains all the packages and dependencies installed in the project.

Whenever you run:

```bash
npm install
```

NPM downloads all required packages and stores them inside the `node_modules` folder.

---

## Example

If you install Express:

```bash
npm install express
```

The folder structure becomes:

```text
node_modules/
└── express/
```

---

## Why is it Important?

Without this folder:

* Express cannot run
* MongoDB drivers cannot run
* JWT authentication packages cannot run
* Any installed library becomes unavailable

---

## Should We Upload node_modules to GitHub?

❌ No

Reasons:

* Extremely large in size
* Can contain thousands of files
* Anyone can regenerate it using:

```bash
npm install
```

The `package.json` file is the heart of every Node.js application.

# 🔒 package-lock.json

## What is package-lock.json?

This file is automatically generated by NPM.

It stores the exact versions of all installed dependencies and their sub-dependencies.

---

## Why is it Needed?

Suppose your package.json contains:

```json
"express": "^5.1.0"
```

Different developers may install slightly different versions.

The `package-lock.json` ensures:

✅ Same dependency versions

✅ Consistent installations

✅ Stable builds

---

## Should We Upload It To GitHub?

✅ Yes

Always commit:

```text
package-lock.json
```

to version control.

---

# 🔐 .env

## What is a .env File?

The `.env` file stores sensitive information and configuration values.

Example:

```env
PORT=5000
MONGODB_URI=your_database_connection_string
JWT_SECRET=your_secret_key
```

---

## Why Use It?

Instead of writing:

```javascript
const password = "mySecretPassword";
```

Use:

```javascript
process.env.JWT_SECRET
```

This improves security.

---

## Installing dotenv

```bash
npm install dotenv
```

---

## Loading Environment Variables

```javascript
require("dotenv").config();
```

---

## Accessing Variables

```javascript
const PORT = process.env.PORT;
```

---

## Important Security Rule

Never push:

```env
JWT_SECRET=
DATABASE_URL=
API_KEY=
```

to GitHub.

---

# 🚫 .gitignore

## What is .gitignore?

`.gitignore` tells Git which files and folders should not be uploaded to GitHub.

---

## Example

```gitignore
node_modules/
.env
```

---

## Why Use It?

### Ignore node_modules

Because:

* Large size
* Can be regenerated

### Ignore .env

Because:

* Contains secrets
* Protects credentials

---

## Recommended .gitignore

```gitignore
# Dependencies
node_modules/

# Environment Variables
.env

# Logs
*.log

# Build Files
dist/
build/

# IDE Files
.vscode/
.idea/

# OS Files
.DS_Store
Thumbs.db
```

# 🛠 Common Deployment Errors

## Module Not Found

Error:

```text
Cannot find module
```

Fix:

```bash
npm install
```

---

## Environment Variable Undefined

Error:

```text
process.env.MONGODB_URI undefined
```

Fix:

Add the variable inside Render Environment Settings.

---

## Port Binding Error

Wrong:

```javascript
app.listen(5000);
```

Correct:

```javascript
const PORT = process.env.PORT || 5000;

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
```

---

## Root Directory Issue

If your backend resides inside:

```text
Backend/Programming-Server
```

Then Render Root Directory must also be:

```text
Backend/Programming-Server
```

Otherwise deployment will fail.

# 🌐 What is a Server?

A server is a program that listens for requests from clients (such as web browsers, mobile apps, or other applications) and sends back responses.

In simple words:

> A server acts as a middleman between the user and the database or application logic.

---

## Real-Life Example

Imagine a restaurant:

### Customer (Client)

The customer places an order.

```text
"I want a burger."
```

### Waiter (Server)

The waiter takes the order to the kitchen and brings back the food.

### Kitchen (Database/Application)

The kitchen prepares the food.

---

### Flow

```text
Client (Browser/App)
         ↓
      Server
         ↓
     Database
         ↓
      Server
         ↓
Client Receives Response
```

The server receives a request, processes it, communicates with the database if needed, and returns a response to the client.

---

## What Does a Server Do?

A server can perform many tasks:

### 1. Handle Requests

Example:

```http
GET /students
```

The server receives the request and processes it.

---

### 2. Send Responses

Example:

```json
[
  {
    "name": "Divyanshu",
    "course": "MCA"
  }
]
```

The server sends the requested data back to the client.

---

### 3. Connect to Databases

The server can:

* Store data
* Read data
* Update data
* Delete data

Example:

```text
MongoDB
MySQL
PostgreSQL
```

---

### 4. Authentication & Authorization

The server can:

* Register users
* Login users
* Verify passwords
* Generate JWT tokens
* Protect private routes

---

### 5. Business Logic

The server performs calculations and validations before sending data.

Example:

```javascript
if (user.age < 18) {
  return res.status(403).json({
    message: "Access Denied"
  });
}
```

---

# ⚡ What is a Node.js Server?

A Node.js server is a JavaScript program that runs outside the browser and listens for incoming requests.

Example:

```javascript
const express = require("express");

const app = express();

app.get("/", (req, res) => {
  res.send("Server is running successfully!");
});

app.listen(5000, () => {
  console.log("Server started on port 5000");
});
```

---

## How This Code Works

### Step 1

```javascript
const express = require("express");
```

Imports the Express framework.

---

### Step 2

```javascript
const app = express();
```

Creates an Express application.

---

### Step 3

```javascript
app.get("/", (req, res) => {
  res.send("Server is running successfully!");
});
```

Creates an API endpoint.

When someone visits:

```text
http://localhost:5000/
```

The server responds with:

```text
Server is running successfully!
```

---

### Step 4

```javascript
app.listen(5000);
```

Starts the server and listens for requests on port 5000.
